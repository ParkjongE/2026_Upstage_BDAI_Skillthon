# 카테고리 매핑표

네이버 데이터랩 쇼핑인사이트 카테고리 체계와 통계청 온라인쇼핑동향조사
(통계표 DT_1KE10041) 상품군 체계는 서로 다른 표준을 씁니다. 이 표에
"확인 필요"로 남아있는 카테고리는 **분석하지 않고 매핑 필요로 응답**합니다
(SKILL.md 경계 원칙 참조) — 절대 이름이 비슷하다고 임의로 연결하지 않습니다.

⚠️ 네이버 카테고리 코드는 공식 코드표가 없고, 네이버 쇼핑에서 해당 카테고리
클릭 시 주소의 `cat_id` 값을 직접 확인해야 합니다
(네이버 공식 개발가이드에 명시된 방법). 아래 표의 "확인 필요"는 이 방법으로
채워야 합니다.

## 매핑표 (우선순위 카테고리부터)

`자연어 별칭` 칸은 사용자가 category_key 대신 흔히 쓸 법한 한국어 표현을
쉼표로 구분해 나열한다. `scripts/run_pipeline.py`의 `resolve_category_key()`가
이 칸(과 category_key, 네이버/통계청 명칭)을 기준으로 자연어 입력을
category_key로 자동 변환하므로, 실제 서비스 문장에서 자주 쓰일 표현을
채워둘수록 "카테고리를 못 찾아 리포트가 안 나오는" 실패가 줄어든다.
새 별칭을 추가해도 되돌아가 검증할 필요는 없다 — 어차피 이 표에 있는
category_key로만 귀결되므로 매핑 자체의 신뢰도에는 영향이 없다.

- 네이버 쇼핑인사이트 연동(`shopping/v1/categories`)으로 `50000003`,
  `50000004`, `50000005`, `50000006`, `50000007`, `50000008`,
  `50000055`, `50000155`, `50000173`, `50000174`, `50000176`,
  `50000177`이 2026-01~2026-03 월별 데이터를 반환하는 것을 확인.
- 네이버 쇼핑 공개 검색 응답에서 `자동차용품` 검색 결과의
  `lCatId=50000008, mCatId=50000055`, `반려동물용품` 검색 결과의
  `lCatId=50000008, mCatId=50000155`를 확인.
- `신발` 검색 결과는 `mCatId=50000173/50000174`, `가방` 검색 결과는
  `mCatId=50000176/50000177`로 성별 하위 카테고리가 갈라져 있음. 네이버
  상대지수를 임의 합산하면 경계 원칙에 어긋날 수 있어 자동 실데이터
  분석은 보류한다.
- `도서`의 대분류 후보 `50000011`은 응답 상태 200을 반환하지만 월별 데이터 배열이
  비어 있어 실데이터 자동 분석 대상으로 확정하지 않는다.

**매핑 불가/보류 (네이버 쇼핑 카테고리 체계와 성격이 안 맞음)**
- `여행 및 교통서비스`, `문화 및 레저서비스`, `이쿠폰서비스`, `음식서비스`,
  `기타서비스` → 이들은 "상품"이 아니라 "서비스"라 네이버 쇼핑인사이트
  (상품 클릭 기반) 카테고리와 1:1 매칭이 어려울 수 있음. 매핑 시도 전
  네이버 쇼핑 사이트에 해당 서비스 카테고리가 실제로 존재하는지부터 확인.
- `기타`, `농축수산물`(식품 하위로 흡수 가능성) → 후순위

## 매핑 추가 절차 (실제로 해야 하는 것)
1. [shopping.naver.com](https://shopping.naver.com) 에서 대상 카테고리 클릭
2. 주소창에서 `cat_id=` 뒤 숫자 확인 → 위 표의 네이버 코드 칸에 기입
3. 코드가 통계청 상품군 1개와 정확히 1:1이 안 맞으면(예: 네이버는 세분화,
   통계청은 큰 카테고리 하나), N:1 매핑 허용하되 그 사실을 리포트 한계
   문단에 명시
4. 검증 상태를 "초안" → "검증완료"로 갱신
5. 사용자가 실제로 쓸 법한 한국어 표현을 `자연어 별칭` 칸에 쉼표로 추가.
   중복돼도 괜찮다(다른 category_key와 겹치면 `resolve_category_key()`가
   후보가 여럿이라고 보고하고 사용자에게 되물으므로, 겹치는 별칭을
   빼거나 더 구체적인 표현으로 좁혀서 정리)
